# Welcome Speech
#### 송재하 - 카카오 CTO

## 거버넌스 / 데이터
* 같은 숫자인데 왜 팀마다 다르지? 이 데이터 지금 써도 될까?
* 데이터의 뜻을 코드로 맞추고 위험을 측정
* 문제가 보이면 누가 맡아서 바로잡을지까지 이어져야 함
* 팀의 약속이 실제로 지켜지도록 도구로 만드는 이야기

## 모델 / 에이전트
답을 어디까지 믿고 쓸 수 있는가
* 전문가 에이전트 연결, 답의 근거 제시
* 같은 GPU로 더 많은 요청 처리
* 교통 예측 모델 교체
  * LLM은 실험을 돕고, 실제 예측은 9MB짜리 작은 모델이 담당
  * AI를 쓴 결과가 꼭 더 큰 모델일 필요는 없음
  * 모델을 바꾸며 정확도와 비용을 어떻게 확인했는지

## AI-DLC
AI와 함께 일하는 방식
* 현장의 병목을 찾는 엔지니어
* AI 산출물을 검증하는 품질 게이트
* 디자인 화면 구현

## 작은 도구가 플랫폼이 되기까지
"쓰레기는 먼저 본 사람이 줍는다" -> 내 눈에 먼저 들어온 문제는 내가 먼저 움직인다
* 내가 불편해서 작은 것부터 만듦 -> 동료들이 써보고 좋아함 -> 고치고 붙이다 보니 함께 쓰는 도구가 됨
* 지금은 동료들이 필요한 도구를 직접 만드는 플랫폼으로 성장
* 남이 쓰기 시작하면 신경 쓸 일도 늘어남 -> 13:30 Conference room 세션

## 같은 기술, 다른 이유
검색 색인을 CDC로 바꾸는 두 세션
* 11:00 AI-DLC 트랙 [옮기는 것보다 증명이 어렵다](./cdc-search.md): 옮긴 결과가 맞는지 어디까지 검증했나
* 15:30 안정성과 인프라 트랙: 잘 돌아가던 폴링을 왜 바꿔야 했나

같은 기술도 여건에 따라 바꿀 이유와 검증 범위가 달라짐 -> 우리 팀은 뭘 확인해야 하나

## 세션 사이사이
